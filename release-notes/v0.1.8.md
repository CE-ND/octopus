# Octopus v0.1.8

这一版加入供应商插件系统、插件商城和更完整的 Agent 配置能力，并修复插件流式请求、渠道显示与 DSH/Kimi Code 接入问题。

## 新功能

### 供应商插件系统

- 支持从 npm 包、本地目录或 `.tgz` 安装供应商插件。
- 插件可作为独立 provider 接入，登录、签名、模型列表和上游请求都由插件负责。
- 支持 API Key、浏览器登录和桌面登录等认证方式。
- 插件 provider 会自动同步为受管渠道，渠道只读，由插件页统一管理。
- 插件宿主按需启动，仅监听本机回环地址，并通过随机令牌保护控制接口。

### 插件商城

- 新增「插件商城」，从配置的 npm 账号或组织展示可用插件。
- 展示插件名称、版本、发布者和描述，支持下载安装与更新。
- 商城插件安装后会显示已安装状态，点击卡片或「管理」可查看 provider、模型和登录状态。
- 当前 WorkBuddy 插件由独立仓库维护：`https://github.com/CE-ND/Octopus-plugin`。

### Agent 配置

- 完善 DSH 桌面配置的读取、写入、冲突检测和自动配置流程。
- 识别 Kimi Code，并支持将 Octopus 密钥和模型分组写入 Kimi Code 配置。
- 改进 Agent 配置弹窗的布局、滚动和配置字段展示。

## 修复与改进

- 修复插件路由在 URL 编码插件 ID 下返回 404 的问题。
- 修复插件请求携带 `Expect: 100-continue` 时上游请求失败的问题。
- 修复流式回复完成后客户端关闭连接被误记为 `context canceled` 的问题。
- 修复 Windows 下插件目录被宿主占用导致升级、卸载失败的问题。
- 插件渠道在渠道列表中显示「插件渠道」标识，并禁止手动编辑或删除。
- 插件配置支持 `octopus.ui.configSchema` 自动表单、自定义页面沙箱 iframe 和 `octopus.replaces` 旧 ID 迁移。

## 安装包

- **Windows x64**：Octopus 自定义安装器（`.exe`）。
- **Mac Apple Silicon**：ARM64 DMG。
- **Mac Intel**：x64 DMG。

Mac 包采用 ad-hoc 签名，首次打开方式见 [桌面端说明](https://github.com/CE-ND/octopus/blob/v0.1.8/DESKTOP.md)。
